# Технические требования

Статус: этап 2, решено ✅.

## 1. Что следует из концепта ✅
- Только онлайн, у каждого своё устройство ([formats.md](formats.md)).
- **Скрытая информация:** чужие руки и содержимое пачек нельзя отдавать клиенту — иначе читы тривиальны. Значит, **сервер авторитарный**: держит колоду, руки, стопку и считает правила; клиент — только отображение и ввод.
- Фишки, рейтинг, лиги, таблицы лидеров меняются только на сервере ([economy.md](economy.md)).
- Платформы: Android → iOS → Web (Яндекс Игры, VK Play) → Telegram Mini App → Steam ([audience.md](audience.md)).

## 2. Стек ✅
- **Клиент:** Godot 4.7, GDScript, 2D, рендерер **Compatibility** (веб + слабые телефоны). Архитектура — правила `.claude/rules/` (HFSM, изолированные сцены, Resource-события, UI в редакторе).
- **Бэкенд:** **Nakama** + Postgres (как в GoofyBalls) — аккаунты, друзья, группы, матчмейкер, кошелёк, лидерборды, хранилище, сокеты.
- **Партия:** **авторитарный матч Nakama** (match handler на TypeScript) ✅. Правила, раздача, добор, боты, таймер — внутри матча.

### Где живут правила — решено: А ✅
| | **А. Nakama match handler (TS)** ✅ | Б. Headless Godot-серверы |
|---|---|---|
| Код правил | TypeScript на сервере, клиент без правил | GDScript, один код с клиентом |
| Инфраструктура | Только Nakama, масштабируется сама | Флот Godot-процессов + аллокатор + Nakama для меты |
| Стоимость | Низкая: пошаговая игра, тысячи столов на один узел | Выше: процесс на N столов, оркестрация |
| Офлайн | Нет (и не нужен — только онлайн) | Возможен |
| Риск | Правила на другом языке, чем клиент | Сложнее эксплуатация |

Выбрано **А**: игра пошаговая, трафик мизерный, а «только онлайн» снимает нужду в правилах на клиенте. Клиент знает только то, что нужно для UI (какие номиналы ещё в игре, можно ли сделать ход).

## 3. Протокол партии ✅
- Клиент шлёт **намерения**: `start_round {cards[], rank}`, `transfer {cards[]}`, `check {index}`, `react {id}`. Сервер проверяет законность.
- Сервер шлёт **каждому своё**: свою руку целиком; у соперников — только число карт и минусы; стопку — числом карт и размерами пачек; открытую при проверке карту — всем.
- Колода тасуется на сервере криптостойким RNG; seed партии сохраняется в логе для разбора споров.
- Таймер хода (20 с) — на сервере; по истечении ходит бот ([formats.md](formats.md)).
- Переподключение: клиент получает полный снимок своего вида стола; ушёл дольше 2 ходов — играет бот, вернулся — продолжает.

## 4. Боты ✅
- На сервере, внутри матча. Уровни силы + «характеры» (осторожный / наглый / сыщик).
- Видят только то, что видел бы человек на их месте (без подсматривания) — честность для платных столов.
- Человеческое поведение: задержка 1–6 с, реакции, редкие ошибки. Сценарные боты для онбординга.

## 5. Мета-сервисы (Nakama) ✅
| Что | Как |
|---|---|
| Вход | Гостевой по устройству сразу, привязка Google / Apple / Telegram (VK — позже, вместе с VK Play) без потери прогресса |
| Друзья, компании | Nakama friends + groups («Компании»), постоянная ссылка компании |
| Приглашения | Deep links: Android App Links, iOS Universal Links; отложенная ссылка — свой сервис (см. ниже) |
| Пуши | FCM (Android/web) + APNs (iOS) через серверный модуль |
| Матчмейкинг | Nakama matchmaker по MMR, при заполнении — старт, на 20-й секунде свободные места занимают боты |
| Кошелёк | Nakama wallet с леджером; любые изменения фишек — только серверные RPC |
| Рейтинг | Glicko-2 на сервере после партии; лиги и сезоны — серверные данные |
| Лидерборды | Nakama leaderboards: фишки (глобально, друзья), Легенда сезона, недельный выигрыш |
| Модерация | Фильтр ников, жалобы, блок-лист для матчмейкинга |

## 6. Платформы ✅
- **Android:** Google Play + RuStore (свой биллинг и пуши RuStore).
- **iOS:** App Store, Sign in with Apple обязателен, если есть другие соцвходы.
- **Web:** однопоточный экспорт Godot (без требований cross-origin isolation), Brotli-сжатие, цель загрузки < 10 МБ первого пакета. SDK Яндекс Игр / VK — в платформенном контексте HFSM.
- **Telegram Mini App:** тот же web-билд + Telegram WebApp API (вход, «поделиться в чат»). Проверить вес и скорость старта на прототипе.
- Платёжные и рекламные SDK — только в платформенных контекстах HFSM (`App/Platform`).

## 7. Клиент ✅
- 60 fps на слабых Android (2 ГБ RAM), портретная ориентация (одна рука, как мессенджер), до 10 игроков за столом на экране телефона.
- Локализация RU + EN (Godot TranslationServer, CSV/PO), все строки через ключи.
- Локально — только настройки; прогресс и фишки — на сервере.
- Логи по `.claude/rules/logging.md`, без чужих рук в логах выше `DEBUG`.

## 8. Аналитика и реклама ✅
- Аналитика: воронка онбординга, D1/D7/D30, длина сессий, доля ботов за столами, экономика (источники/сливы фишек). RU: AppMetrica, мир: Firebase / GameAnalytics (см. ниже)
- Реклама за награду: Yandex Mobile Ads (RU) + AdMob (остальные)

## 9. Тесты ✅
- Правила на сервере — юнит-тесты по сценариям (сид → ходы → ожидаемое состояние), включая все крайние случаи из [rules.md](rules.md).
- Симуляция ботов: тысячи партий бот-против-бота — проверка, что партия всегда заканчивается, и замер длины сессий.
- Клиент — headless-тесты сцен (каждая сцена стартует сама, F6).

## 10. Хостинг ✅
- **Старт (RU/СНГ):** один регион в российском облаке (Yandex Cloud / VK Cloud / Selectel / Timeweb) — Nakama + Postgres в Docker, как в GoofyBalls. Нужно по 152-ФЗ: персональные данные граждан РФ хранятся в РФ.
- Персональные данные у нас: ID соцвходов (Telegram, Google, Apple, позже VK), имена/аватары/email оттуда, друзья и компании; серая зона — ID устройства, IP, пуш-токены, ID чеков, данные SDK аналитики.
- **Выход на мир:** второй регион за рубежом — отдельная копия Nakama со своей БД для игроков не из РФ (в т. ч. ради GDPR). Матчмейкинг по регионам раздельный.
- Пошаговой игре задержка не важна: один российский сервер нормально обслуживает и зарубежных игроков на этапе тестов.

## 11. Юридическое ⚠️
- **Выплаты от сторов и рекламы** (Google Play, Apple, AdMob) российским юрлицам/счетам ограничены с 2022 → заранее решить вопрос с юрлицом/аккаунтом разработчика (часто — компания в другой стране). Важнее выбора хостинга; уточнить у специалистов перед публикацией.
- Часть западных SDK (атрибуция, аналитика) может ограничивать аккаунты, связанные с РФ — проверять каждый.
- Политика конфиденциальности, GDPR для ЕС, удаление аккаунта из приложения (требование сторов).
- Возрастной рейтинг по анкетам сторов: до пакетов фишек — ориентир 12+/16+, после — 17+/18+.
- Перед запуском — консультация юриста по 152-ФЗ (границы для гостевых ID и IP).

## Приглашения, аналитика, ориентация ✅
1. **Ссылки-приглашения — свой простой сервис, без платных SDK на старте.**
   - Ссылка вида `bluff.<домен>/r/<код>` → веб-страница: игра установлена — открывается сразу за столом (App Links / Universal Links); нет — кнопка в стор.
   - Android: код комнаты передаётся через **Play Install Referrer** (бесплатно, надёжно) — после установки игрок сразу попадает за стол.
   - iOS: надёжного бесплатного способа нет → после установки экран «Тебя пригласили? Вставь код» с автоподстановкой из буфера (по согласию). Код комнаты короткий (6 символов).
   - Telegram Mini App снимает проблему совсем: ссылка в чате открывает стол без установки.
   - Платная атрибуция (AppsFlyer и т. п.) — только когда начнём закупать рекламу.
2. **Аналитика и реклама по регионам:**
   - RU/СНГ: **AppMetrica** (аналитика) + **Yandex Mobile Ads** (реклама за награду) — работают с РФ без ограничений.
   - Мир (позже, второй регион): Firebase/GameAnalytics + AdMob.
   - Свои ключевые события (онбординг, экономика, доля ботов) дублируем в логи Nakama — не зависим от SDK.
3. **Ориентация:** телефон — **только портрет** (одна рука, как мессенджер; Telegram тоже портрет); ПК и веб на десктопе — **ландшафт** с тем же столом по центру и боковыми панелями.
